# Curio Clerk 자율 품질 점검 / Autonomous quality review

목표는 사용자가 결함을 하나씩 찾아 지시해야 하는 상황을 줄이는 것이다. 에이전트는 승인된 게임 작업 안에서 직접 문제를 발견하고, 영향이 큰 문제부터 수정하고, 수정된 실행 결과까지 확인한다. 이 문서는 실행 중인 작업의 개발 규칙이며 예약 작업이나 상시 실행 서비스를 설치하지 않는다.

## 한 사이클의 실행

1. **기준 확인:** 현재 프로젝트·브랜치·커밋·dirty 파일과 실행할 APK의 소스를 확인한다. 최신 QA와 아래 미해결 항목을 읽는다. 예전 후보의 문제는 현재 버전에서 다시 확인하기 전까지 역사적 증거로 표시한다.
2. **화면부터 보기:** 가능하면 소스·정답·기존 풀이를 전달하지 않은 별도 검토자에게 현재 화면이나 짧은 플레이 기록을 준다. 검토자는 현재 목표, 눌러볼 곳, 예상 결과를 먼저 기록한다. 이미 정답을 아는 에이전트라면 그 사실을 명시한다. 스크린샷 검토를 실제 입력이나 사람의 첫 플레이로 표현하지 않는다.
3. **실제 입력으로 확인:** 선택한 장면을 전용 QA 환경에서 진행한다. 합리적으로 보이는 오답, 관찰 생략, 도구가 선택된 상태에서 힌트 사용, 재시작·메뉴 왕복도 필요한 범위에서 시도한다. 같은 실패를 반복해도 새 정보가 없거나 화면에 없는 사실을 알아야 진행된다면 문제로 기록한다.
4. **우선순위 선택:** 진행 불가·저장 손실(P0/P1), 행동을 오해하게 하는 안내·상태 불일치(P1/P2), 문구·시각적 다듬기(P2/P3) 순서로 처리한다. 심각도는 실제 영향에 맞춰 정하며, 한 번에 하나의 일관된 문제 묶음을 해결한다. 확인되지 않은 재미 문제는 가설로 남긴다.
5. **수정과 검증:** 행동 변경은 재현 테스트를 먼저 실패시킨 뒤 고친다. 문구·그림 변경은 출처 문서를 먼저 갱신한다. 수정자가 아닌 검토자가 가능한 범위에서 결과를 다시 확인한다. 관련 Editor 검사와 원래 문제가 나타난 실제 입력·화면을 통과해야 해결로 표시한다.
6. **통합과 인계:** 요청 범위의 검증을 마친 뒤 소스·QA·문제 목록을 함께 갱신한다. 이미 확인된 큰 문제를 남겨둔 채 낮은 우선순위의 장식 작업으로 넘기지 않는다. 범위 안의 다음 중요한 결함이 있으면 이어서 처리한다. 범위를 벗어나거나 외부 조건으로 확인할 수 없으면 근거와 다음 확인 조건을 남긴다.

## 플레이 경험 통과 기준

| 관점 | 확인할 내용 | 증거 |
|---|---|---|
| 목적과 몰입 | 내가 누구이고, 지금 무엇을 해결하며, 해결하면 무엇을 알거나 바꾸는지 화면에서 파악할 수 있다. 다음 장면이 앞선 행동의 결과와 연결된다. | 실제 도입·목표·결과 문구와 화면; 판단이 필요한 부분은 가설로 기록 |
| 조작과 관찰 | 대상·도구·현재 선택 상태를 구분할 수 있다. 관찰 같은 선행 조건을 알 수 있고, 실패해도 다음 시도에 쓸 정보를 얻는다. | 선택·관찰·잘못된 시도 전후 실제 입력 기록 |
| 막힘에서 회복 | 도움을 직접 찾을 수 있고, 현재 상태에 맞는 단서를 얻는다. 자세한 도움을 따라 도구나 관찰을 실행할 수 있으며 미래 단서로 안내하지 않는다. | 미관찰·관찰 완료·선행 행동 완료 전후 힌트와 실제 입력 |
| 행동과 결과 | 중요한 작업의 결과가 화면에 나타난다. 그림과 글이 같은 물건·위치·상태를 말하며 다음 작업의 단서를 가리지 않는다. | 작업 직전/직후 짝지은 화면 또는 영상; 완료 화면만으로 중간 상태를 통과시키지 않음 |
| 반복과 선택 | 같은 조작을 반복하더라도 새 단서·물건 변화·사연의 진전이 있다. 새로운 단어만 읽고 같은 일을 반복하는 구간을 찾아 개선 가설을 세운다. | 장면별 행동과 새 정보의 기록; 재미 점수는 임의로 만들어 통과 판정하지 않음 |
| 한영 문구 | NPC가 자연스럽게 말하고, 메뉴는 실제 동작을 설명한다. 잘림·모호한 지시·어색한 조사·단어 중간 줄바꿈을 확인한다. | 영어/한국어의 실제 작은 세로 화면과 긴 문장; 검사한 해상도 명시 |
| 신뢰성 | 오프라인 진행, 완료 지점 저장, 재개·재시작·다시보기의 약속을 지킨다. 실패나 힌트가 재화·광고·대기를 강요하지 않는다. | 적절한 자동 검사와 기기 입력·저장 전후 대조 |

기술 검사 통과, 에이전트의 화면 판단, 소스를 아는 완주, 사람의 자연 플레이는 각각 구분한다. 여러 에이전트가 동의해도 사람의 재미·이해도를 검증한 것은 아니다. 자연 플레이 참가자에게 답을 알려 준 뒤 완료했다면 도움을 받은 결과로 기록한다.

## 검증 비용과 작업 환경

- 소스·화면의 저렴한 검토로 문제를 먼저 모으고, 하나의 관련 수정 묶음에 필요한 검사를 수행한다. 문서만 바꿨다면 Unity나 APK를 다시 빌드하지 않는다. 통과한 동일 검사를 새 변경이나 의심 없이 반복하지 않는다.
- Android 동작·아트·레이아웃 수정의 인계에 개발 APK가 필요하면 저장소 스크립트로 빌드한다. 기존 APK와 companion 출력을 먼저 보관하고 새 후보는 고유 경로에 둔다. BuildAll과 버전·설정 원칙은 AGENTS.md를 따른다.
- Unity를 실행하는 작업자는 한 명만 둔다. 검토 에이전트는 읽기 전용으로 동작하고, 파일 편집 담당 범위를 겹치지 않는다. 빌드·소스 보존 대조 중에는 검사 대상 파일을 동결한다.
- 사람의 플레이 환경에 자동 입력·업데이트·재시작을 하지 않는다. 전용 QA 저장과 기기만 사용하고 실제 기기 식별자를 조작 직전에 확인한다. 계정·동의·광고 없이 검증한다.
- 작업 종료 때 완료한 수정, 남은 상위 문제, 검증한 후보와 검사하지 못한 범위만 간결하게 알린다. 작업이 끝난 뒤 저절로 계속 실행되는 것으로 표현하지 않는다. 예약 실행은 별도 요청으로 설정하고, 켜진 PC·사용 가능한 프로젝트·권한과 중복 실행 방지를 확인한다.

## 다음 작업에서 사용할 짧은 지시

> Docs/QualityReview.md에 따라 현재 두 사건의 품질 개선 사이클을 실행해. 최신 버전에서 상위 미해결 문제를 확인하고, 필요한 수정을 스스로 선택해 구현·검증·기록까지 마쳐. 정답을 아는 완주와 화면만 보는 검토를 구분하고, 실제 사람의 재미를 확인했다고 주장하지 마. 사용자 플레이 환경과 기존 파일·산출물을 보존하고, 병합·출시는 하지 마. 통상적인 구현 판단은 다시 묻지 말고 진행해.
